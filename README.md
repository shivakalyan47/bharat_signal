# BharatSignal: National Geospatial Intelligence Platform

## 1. Executive Summary
**BharatSignal** is an advanced, automated intelligence platform that aggregates real-time data across India and correlates it into a unified, predictive situational awareness map. Rather than just plotting data points, it acts like an AI intelligence analyst: it reads news, monitors weather and traffic, groups related events together, predicts what will happen next, and self-corrects its logic over time.

## 2. Core Capabilities
* **Continuous Live Ingestion**: A background daemon continuously polls multiple global APIs every 2 minutes to gather fresh intelligence on disasters, weather extremes, traffic, and breaking news.
* **NLP Intelligence Extraction**: Reads unstructured news headlines and descriptions, automatically identifying the severity, geographic location, and specific domain concepts (e.g., "terror attack", "flood risk", "hospital surge").
* **AI Correlation & Clustering**: Instead of showing 100 isolated alerts, the system calculates semantic, spatial, and temporal similarity scores to group related signals into unified **Incidents** and broader **Situations**.
* **Predictive Forecasting (ML)**: Uses a Random Forest machine learning engine with over 70 causal rules (e.g., Heavy Rainfall ➔ Waterlogging ➔ Traffic Congestion) to predict cascading secondary effects before they happen.
* **Self-Correcting Reality Loop**: The system evaluates its own past predictions against incoming live data. If a predicted traffic jam never happens, the ML engine dynamically adjusts its causal weights to improve future accuracy.

## 3. Data Sources (Active Integrations)
The platform is currently wired into the following live APIs:
* **News & Media**: NewsAPI, WorldNewsAPI, GNews API, Currents API (processes Indian news, identifies disaster/emergency keywords).
* **Weather**: OpenWeatherMap (monitors 30 major Indian cities for heatwaves, storms, etc.), Open-Meteo (grid-based historical/live data).
* **Traffic & Transport**: TomTom Traffic API (monitors congestion ratios across 20 major Indian cities).
* **Global Disaster Monitors**: USGS (Earthquakes), NASA EONET (Natural events), GDACS (Disaster alerts).

## 4. Codebase Architecture Guide
The project is built entirely in Python (Backend) and vanilla HTML/JS (Frontend). It is designed to run locally.

* `apps/intelligence/live_worker.py`: The background daemon. You run this to start the 2-minute polling loop.
* `apps/intelligence/pipeline.py`: The central nervous system. It orchestrates the flow from raw signals ➔ correlation ➔ clustering ➔ forecasting ➔ reality loop.
* `apps/intelligence/correlation/`: The "Brain".
  * `engine.py`: Calculates similarity between signals.
  * `ml_engine.py`: The Random Forest predictive model.
  * `reality_loop.py`: The self-correction mechanism.
* `apps/intelligence/ingestion/sources/`: Contains the specific scripts connecting to TomTom, OpenWeather, GNews, etc.
* `apps/intelligence/dashboard/`: The frontend. `index.html` and `app.js` read the `pipeline_data.json` file generated by the backend and render the Leaflet (OpenStreetMap) interactive map.

## 5. How the Data Flows
1. **Ingestion**: The `live_worker` wakes up and queries all APIs.
2. **Normalization**: Every raw data point is converted into a standardized `Signal` object with a unified timezone-aware timestamp and a severity score (0 to 1).
3. **Correlation**: The pipeline compares every signal against every other signal, scoring how related they are.
4. **Clustering**: Highly related signals are merged into an `Incident`. Related incidents are grouped into a `Situation`.
5. **Prediction**: The `MLEngine` looks at the active situations and generates `Forecasts` for what will happen next.
6. **Export**: The entire state is exported to `dashboard/pipeline_data.json`.
7. **Visualization**: The dashboard auto-refreshes every 2 minutes, loading the new JSON and updating the map.

## 6. Maintenance & Operation
To run the project, two terminal commands are required (these are currently running in the background):
1. **Start the AI Worker**: `python -m apps.intelligence.live_worker --interval 120`
2. **Start the Dashboard**: `python -m http.server 8080 --directory apps/intelligence/dashboard`

If you ever need to reset the system's memory, you can delete the `apps/intelligence/dashboard/pipeline_data.json` file and the `apps/intelligence/models/rf_model.pkl` file, and restart the worker.
